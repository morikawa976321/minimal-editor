# ネイティブ版の比較 · 2026-10-18

## 開く

リポジトリ直下の **`ネイティブ比較.vbs`** をダブルクリック。比較ページの「開く」でブラウザ版／ネイティブ版をそれぞれ起動する。通常の **Win → minimal-editor → Enter** はブラウザ版を継続する。

ネイティブ版だけなら **`ネイティブ版.vbs`**。初回の原稿コピーだけ短時間Nodeを使い、以後はexeへ直接渡す。エディター本体はRustの単独プロセスで動き、ブラウザ・常駐Nodeサーバーは必要ない。

比較ページ自体はEdgeと小さなローカルNode補助を使う。ページを閉じると補助は最後の通信から90〜100秒後に終了する。ネイティブ本体のメモリ測定にはこれらを含めず、測定対象を明示する。両画面や比較ページを開いたままのPC全体の消費量が、ネイティブ単体の値になるわけではない。

## 原稿の扱い

- ブラウザ版の本文・一覧・起動先は変更しない。
- ネイティブ初回起動時だけ、ブラウザ版のメモ・手動タイトル・作成順・アーカイブ・現在のメモを `data/native-next/` へコピーする。その後は独立して保存し、相互に同期しない。
- コピーは既存のネイティブ保存先を上書きしない。失敗・不完全な保存先を空として作り直さない。コピー中に観測できた元ファイルの変更はエラーにするが、複数ファイルを一つのトランザクションとして取得する機構ではない。
- 本文は `data/native-next/memos/<id>.txt`、一覧・手動タイトル等は `catalog.tsv`。直前版 `.bak` と履歴 `history/` を保持。保存できない時は画面の本文を保持し、切替・終了を止め、有効な本文は `recovery/` に別名で退避する。
- メモ本文・台帳・履歴・比較用コピーはGit対象外。原稿の自動統合・採用版切替・物理削除は行わない。

## 操作

現行の [キー一覧](shortcuts.md) に合わせる。Ctrl+N作成、Ctrl+P通常一覧、Ctrl+Shift+Pアーカイブ一覧、↑↓とEnter、Ctrl+M改名、Deleteアーカイブ、8秒の取消ボタン／一覧内Ctrl+Z、Escと各一覧のショートカットで閉じる。外側クリックでは閉じない。タイトル入力中と本文のCtrl+Zは文字のUndo。IME変換中はアプリ側のショートカットとして使わない。

通常一覧は現在のメモを選択し、作成日降順。アーカイブ一覧のEnterは復元して開く。取消は復元のみで、現在のメモを変更しない（全件保管中の場合を除く）。本文はプレーンテキストとして保存する。

## 見た目と入力の差

背景 `#202020`、文字 `#dfdfdf`、本文20px、最大幅1100px、上60px／左右48px／下48pxの余白、行間36px、中央560pxの一覧、20pxの一時表示スクロールバーを目標に合わせた。狭幅時は上36px／左右24px。DPIに合わせて拡大する。

英数字の既定はIntel One Mono、日本語のフォント関連付けはBIZ UDGothic。ブラウザのCSSフォールバックとWindowsのフォント関連付けは異なるので、全文字の字形・折返し位置の一致は保証しない。

明確な差:

- システムRich Editは字間の `sSpacing` を保持するが、描画には使わない。ブラウザ版の字間0.01emは再現していない。[CHARFORMAT2Wの仕様](https://learn.microsoft.com/en-us/windows/win32/api/richedit/ns-richedit-charformat2w_1)。
- 一覧の背面は半透明ではなく暗い単色。影・ホバー描画・文字の折返し等は完全一致ではない。
- 本文は行間を設定するためRich Editの書式機能を内部で使う。入出力・貼付はプレーンテキストへ制限し、書式ショートカットを抑止する。書式やオブジェクトを原稿ファイルへ保存する機能はない。
- 標準部品のIME・テキスト入力を使うが、このPCの実IMEの配色・候補窓・Handyの実入力は本人の試用で確かめる。以前の標準EDIT版の反転表示が、この版で解消したとは自動試験だけで断言しない。
- 本文のUndoは同じメモを選び直しても維持するが、別メモへの切替を越えての継続は保証しない。独自描画の一覧はブラウザ版のARIA/UI Automationと同等のアクセシビリティを実装したものではない。
- 本文の矢印・PageUp/PageDown等は標準部品で動くが、独自スクロールバーをTabで選んで操作する経路は未移植。

## 再構築と検証

`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-native.ps1`。既存Rustだけを使い、crate・GUIランタイム・追加パッケージの導入はない。製品の実行にはRustのインストールは不要。生成物は `build/native-next.exe`（Git対象外）。

`scripts/test-native.ps1` は保存・初回コピー・起動API・実GUIの隔離試験を直列実行する。GUI試験は非表示の専用desktopで、本人の画面・キーボード・クリップボードを使わない。実IME/Handyの本人試用と同一とは扱わない。

メモリ測定は `tests/native_memory_desktop.py`。測定用の最小構成は `tests/memory_probe.rs` から `build/memory-probe.exe` を構築する。結果と10MBの技術構成は [native-memory-options.md](native-memory-options.md) に記録する。

今回のネイティブ版は14,700字で専用RAM約4.1MiB、40回の追記後でも約4.3〜4.5MiB。共有ページ込みは約29〜30MiB。専用RAMの意味では10MB未満を確認したが、共有込み10MBや長時間・実IME使用中の上限保証ではない。

最終機能試験 `.work/native-next-ui-l7uty0s_/result.json` は実VBSの初回コピーとexe直接起動を含めて合格。比較ページは `.work/native-comparison-ui-54zRoS/result.json` で両起動ボタン（実アプリを開かないstub）・選択／問題トグル・「どちらも問題ない」・結果テキスト・1100px/360px表示を確認。PNGを目視し、JavaScriptエラーなし、試験ブラウザの終了も確認した。結果コピーのクリップボード操作そのものは本人のクリップボードを変更しないため自動実行していない。
