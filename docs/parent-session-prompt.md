## 2. ゴール

**本人がこの PC の前に1回座り、各 V0 で同じ文章をひとしきり書いて、クリックで選ぶだけで最終方式が決まる状態を作る。**

1. **方式の洗い出し**: 実装方式の候補を広く挙げ（例: Edge の `--app` ウィンドウで開く HTML 1枚 ／ Rust のネイティブ GUI ／ Python のネイティブ GUI ／ Windows Terminal で動く TUI ／ その他）、それぞれの「本人の基準との相性」「IME と Handy の通りやすさ」「起動の速さ」「依存の少なさ」を短く評価する。ここで Claude（sonnet）か cursor に独立の意見を1回取る。
2. **V0 を複数（3本以上）作る**: 評価の上位だけでなく、方式として異なるものを選ぶ（同じ技術の派生を3本並べない）。各 V0 は**動くエディター**であること: 起動 → 書く → 自動で残る → 閉じる → 再び開くと続きが出る、まで。設定機能は持たず、決めるべきこと（フォント・文字サイズ・配色・保存先・ファイル形式・ウィンドウの大きさ）は全部 V0 の中で決め切る。決め方の根拠は AGENTS.md 5節の基準に置き、`docs/decisions.md` に書く。V0 間で意図的に違えた決定（例: 自動保存の方式、1ファイルか複数ファイルか、Markdown か素のテキストか）は、何を比べるための違いかを書く。
3. **必須の検証（本人を待たない）**: 各 V0 について、(i) 日本語 IME のインライン変換が動く（自動化できない部分は、動かない既知の構造を避けたことを根拠つきで書く。自前描画のテキスト欄は IME が通らないことが多い）、(ii) Handy のようにフォーカスのある欄へ文字が流し込まれる経路で入力できる（SendInput 相当の自動テストで代替可）、(iii) 1万字を超える文章でも引っかからない、(iv) 強制終了しても直前までの文章が残る、(v) Win キー → 名前 → Enter で起動できる（スタートメニューのショートカットを作る。ショートカット作成は本人の環境への変更なので `%APPDATA%\Microsoft\Windows\Start Menu\Programs` 配下の1ファイルに限り、作ったものを `docs/STATUS.md` に列挙する）。
4. **比較の現物**: HTML 1枚のランチャー兼記録ページを作る。各 V0 をワンクリックで起動でき、本人が書き終えたら「一番いい」「どちらも問題ない」「致命的な問題あり（理由を1クリックで分類: 入力／見た目／速さ／保存／起動）」を押せ、結果がテキストブロックで出る。キーボード操作は要らず、説明文は置かない。
5. **方式の先の検討（プロンプト外も含む）**: 作りながら見えた論点（例: 書いたものをどこに溜めるか、2028年以降の Debian で同じものが動くか、手書きの読み物の場所との接続）は、本人に聞かず、`docs/decisions.md` に「検討した・結論・覆る条件」として残す。可逆で本人を要しないものは試してよい。

## 3. 進め方の注意

- 見た目は足切り条件である。試作でも、ダークテーマ・余白で区切る・説明文を置かない・装飾とアニメーションを足さない、を最初から守る。
- 新しいランタイムやアプリを増やさない。この PC にある Python（uv）・Node 24・Rust・Edge の範囲で作る。どうしても要るものは V0 の中（仮想環境・node_modules・cargo target）に閉じる。
- 本人の画面を奪う検証をしない（AGENTS.md 2節）。GUI の自動テストは、ウィンドウを表示しないモードか、数秒で自動終了する起動で行う。
- 「AIと独立」は、エディターの中に AI 機能を持たないという意味である。作るのに AI を使うことは問題ない。
- `docs/experiment-notes.md` に、Codex を親として動いて詰まった点を1行ずつ残す（本人が Claude 親の4本と比べる）。
